# Phase 5: open the PR

Open the pull request only after a pre-PR PASS in `04-verification.md`.

## Native process

Use the repository's native PR process: its branch naming, commit format, PR
template, reviewers, labels, and required checks. Do not impose another
repository's conventions.

When a policy file names a PR skill, load that skill and follow it. The public
skill does not name a private PR tool.

## After opening

- Return the PR URL as soon as it exists.
- Record the PR number, URL, head SHA, base branch, and CI state in `05-pr.md`.
- Follow the repository's review and CI process. Resolve actionable findings
  caused by the change.
- If the repair loop changes code after the phase 4 PASS, dispatch QA again for
  every affected check and update `04-verification.md` with the new reviewed
  HEAD. Never push newer code with an old PASS.
- Do not merge, deploy, or approve the PR. The user controls those actions.

## Stop condition

Stop after the PR and repair loop. Report the PR URL, the verification verdict,
open CI or review items, and the report paths.
